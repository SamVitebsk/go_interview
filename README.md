# go_interview

## Почему приведение `int64` в `int16` не проверяет диапазон?

В Go явное приведение типов **не выполняет проверок в runtime ради производительности** — операция компилируется в одну процессорную инструкцию.

Под капотом происходит **усечение битов (bit truncation)**: старшие 48 бит просто отбрасываются, а оставшиеся 16 бит интерпретируются как новое число. Никакой `panic` не возникает, данные искажаются «тихо»:
* `32768` превратится в `-32768` (старший бит станет знаковым минусом);
* `65536` превратится в `0` (все младшие 16 бит равны нулю).

### Как делать правильно:
1. При парсинге строк задавать `bitSize = 16` в `strconv.ParseInt(raw, 10, 16)` — функция сама проверит границы и вернёт `strconv.ErrRange`.
2. При работе с готовым `int64` — явно проверять диапазон `[-32768, 32767]` перед приведением.
